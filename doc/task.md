# 多工具中文本地化软件任务计划

更新日期：2026年11月04日。

## 1. 已明确的产品方向

- 交付有现代化 UI 的桌面管理软件，不是先交付脚本、最后再附加界面。
- 首期 Windows、简体中文、本地执行；技术栈已选 Electron + React + TypeScript + Vite。
- 首批软件目录包括 Claude Code、Claude Desktop、Antigravity，依据 [example](../example/) 中的参考项目落实安装检测与汉化检查。
- 核心顺序：打开主页 → 检查已安装的 Agent/软件 → 查看汉化状态和适配情况 → 应用汉化或卸载汉化。
- 「卸载汉化」指撤销本管理器安装的汉化并恢复对应原始资源/配置，不是卸载目标软件，也不是删除用户配置。
- 检测能力与修改能力分开交付：某工具能被检测，不代表当前版本能汉化；参考项目声称支持不等于本软件已验证支持。
- 已交付可运行桌面应用：现代化主页、三工具真实检测、汉化状态检查、操作记录与设置页；Claude Code CLI 支持应用/卸载汉化，Windows 与 Ubuntu 均可用。
- 已提供 Windows NSIS、Ubuntu AppImage 与 deb 安装包；安装包未签名，尚未完成干净环境安装验收。
- Claude Desktop、Antigravity 目前仅检测与状态查看；不执行参考安装脚本，写入能力待各自安全验证后接入。Ubuntu 上 Antigravity 的 ASAR 注入、Claude Desktop deb 的 sudo 修改均未接入。
- 验证范围见 [支持矩阵](support-matrix.md)；隔离环境流程验证不等于真实客户端界面验收。

状态：`[ ]` 未完成，`[x]` 已完成。进行中、阻塞和未验证情况另行注明，不以完成勾选替代。

### 参考源码对检查方案的具体约束

| 工具 | 静态可见机制与依据 | 计划采用的检查方式与限制 |
| --- | --- | --- |
| Claude Code | [插件入口](../example/claude-code-zh/mods/cc-zh/hooks/register.tsx)、[插件描述](../example/claude-code-zh/mods/cc-zh/.claude-plugin/plugin.json)：当前参考为 CLI mods/function-hooks 插件，不是二进制替换；自身未提供完整安装扫描 | 分别识别 CLI 实例与插件装载来源；配置存在仅表示已配置，不能证明当前会话已加载。静态检查与宿主运行验证分别报告；卸载仅撤销对应插件来源，保留其他插件设置，新会话/重新加载后确认生效 |
| Claude Desktop | [Windows 实现](../example/claude-desktop-zh-cn/scripts/install_windows.ps1)：包含本地 app-* 与 AppX 发现、语言资源及前端布局处理；不是单纯切换语言 | 分渠道发现实例，检查 ion-dist 目录或 ion-dist.asar 布局、locale、资源标记与备份归属；补丁发布版本不作为客户端兼容版本。原生中文与参考补丁覆盖范围分开；涉及 exe 完整性/签名或所有权变更的路线须明确限制，不能直接复用 |
| Antigravity | [本地化引擎](../example/antigravity-desktop-cn/localization_engine.js)：读取/修改 app.asar，具有注入标记、手动路径与多来源发现；参考的检查参数入口也可能有副作用 | 单独实现只读资源标记与版本/布局检查，不调用安装器充当检测器；app.asar.bak 存在不等于汉化生效。备份必须绑定实例、版本及原文件指纹，不能升级后直接恢复旧备份 |

三个项目没有可直接统一调用的纯只读状态 API，因此先实现各自的安装发现和状态读取适配器，不封装执行其安装脚本作为「检测」。安装路径与版本声明还须在授权环境复验；参考项目中的签名、权限、附加配置动作不自动纳入本软件功能。

后续矩阵分别记录「参考文档声明」「源码可见」「本项目 fixture 测试」「真实客户端验证」，不合并成一个已支持勾选。卸载恢复须说明内容、配置、权限和签名各自的恢复范围，不承诺无痕恢复。

### 每个工具均须输出的检查结果

1. **安装信息**：是否发现、规范化安装路径、实例标识、产品形态、版本、渠道与架构，以及检测证据。
2. **汉化现状**：是否存在有效汉化、覆盖的是界面/提示/配置中的哪些部分、是否由本管理器安装、有无可验证的恢复资料。
3. **兼容能力**：当前实例能否应用汉化、能否卸载汉化；不能操作时说明具体原因。
4. **风险状态**：文件占用、升级后资源变化、第三方汉化、残留、备份缺失或恢复冲突。

安装检测采用各工具有证据的标准路径、安装登记、命令入口或用户指定路径，不全盘递归搜索，不执行来源不明的可执行文件来读取版本。一个工具多种来源发现同一安装时按实际路径/文件身份去重；不同安装实例不合并。

## 3. 主页与交互规格

### 页面结构

- **侧栏**：软件管理（默认首页）、操作记录、设置；首期不做插件市场或在线服务。
- **顶部**：页面标题、软件名称搜索、重新检测按钮、最近检测时间。
- **筛选区**：已安装 / 全部目录，以及汉化状态筛选；默认关注已安装软件，未安装项仍可通过全部目录查看。
- **主体**：响应式软件卡片或列表，包含图标、名称、产品形态、版本、安装状态、汉化状态与主操作。
- **详情抽屉**：多实例选择、完整路径、检测依据、包版本、覆盖范围、兼容原因、备份及最近操作；长路径不挤压主卡片。
- **操作反馈**：预览与确认对话框、步骤进度、完成/失败结果和恢复入口；不以短暂 toast 作为唯一错误说明。

### 现代化视觉要求

- 克制的中性色底色与统一强调色，明确的文字层级、适度圆角、细边框和留白；装饰不抢占软件管理主体。
- 浅色/深色主题，统一图标、间距、按钮与状态标签；具体 token 在 UI 设计阶段确定。
- 状态同时用文字和图标表达，不只靠红绿颜色；键盘可操作，焦点清晰，正文对比度符合 WCAG AA。
- 适配常见 Windows 窗口尺寸与显示缩放；窄窗口调整列数，长名称和路径可查看完整内容。
- 加载使用骨架或明确进度，动效短且克制，尊重减少动态效果设置；不添加无用途图表或装饰性指标。
- 开发原型允许 mock 数据，但必须标明演示；真实运行时不把 mock 结果当成本机检测结果。

### 状态与操作规则

安装状态、汉化状态、操作能力独立建模，不混为一个布尔值。

| 场景 | 主页展示 | 允许操作 |
| --- | --- | --- |
| 尚未检测 / 检测中 | 待检测 / 检测进度 | 等待、查看目录；检测阶段可取消 |
| 未发现安装 | 未检测到安装 | 手动选择路径、重新检测；不提供汉化按钮 |
| 已安装，未汉化且适配通过 | 未汉化、版本信息 | 预览并应用汉化 |
| 本管理器汉化有效，恢复资料完整 | 已汉化、包版本 | 查看详情、预览并卸载汉化 |
| 已安装但版本未适配 | 已安装、暂不支持该版本 | 查看原因、重新检测；不写入 |
| 检测到第三方汉化 | 外部汉化、未接管 | 查看证据；默认不覆盖、不宣称可安全卸载 |
| 存在标记但不能确认效果 | 汉化状态待确认 | 查看原因与人工验证建议，不直接标为已汉化 |
| 更新后失效 / 部分汉化 / 备份缺失 | 异常及具体原因 | 检查详情；根据真实兼容性与恢复条件决定操作 |
| 部分检测失败 | 保留其他软件结果并单独报错 | 针对失败项重试，不伪装成未安装 |

「卸载汉化」须展示受影响文件和配置字段，保留用户其他设置及之后产生的合法修改；发现冲突停止自动覆盖。外部汉化只有具备明确来源与可验证恢复方案时才考虑显式接管，不作为首期默认能力。
