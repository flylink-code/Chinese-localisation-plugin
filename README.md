# 多工具中文本地化管理软件

面向 Claude Code、Claude Desktop、Antigravity 等工具的中文本地化管理软件，目标是统一管理工具检测、兼容性检查、汉化方案、应用预览、备份恢复与升级后的重新适配。

> 当前处于规划阶段，尚未实现可运行的软件或经过验证的工具适配器。本文中的功能、目录及操作流程均为规划，不代表已经支持。项目暂用当前仓库名称，正式产品名称待定。

## 1. 项目目标

- 将分散的汉化步骤整理为可检查、可复现、可恢复的操作流程。
- 通过独立适配器支持不同工具，不将某一种工具的文件结构或汉化方式写死在通用引擎中。
- 优先汉化用户可见的菜单、按钮、提示和帮助文案，保持命令、配置和程序行为不变。
- 以明确的版本兼容清单代替「通用支持所有版本」的承诺。
- 默认本地处理，不上传安装文件、用户配置、会话、账号信息或日志。

## 2. 当前状态与首期范围

| 项目 | 规划基线 |
| --- | --- |
| 目标语言 | 简体中文（zh-CN） |
| 首期平台 | Windows；macOS、Linux 后续按适配器逐项验证 |
| 产品形态 | 现代化桌面 UI，主页展示软件目录、已安装实例及汉化状态；CLI 不作为首期交付前提 |
| 首批检查范围 | Claude Code、Claude Desktop、Antigravity，参考 example 下三个项目逐项规划检测 |
| 操作范围 | 先检查安装与汉化状态，再按适配能力支持应用汉化及卸载汉化（恢复原文，不卸载软件） |
| 当前实现 | 暂无；候选工具均未验证，暂无支持版本 |
| 技术栈 | 待选型，不预设目标工具的框架、资源格式或安装路径 |

实施顺序为「现代化主页与三类软件目录 → 已安装实例检测 → 汉化状态检查 → 应用汉化 / 卸载汉化」。检测界面不依赖写入引擎先完成，写入能力按工具逐项接入；参考项目存在不代表本软件已验证支持。

### 主页 UI 方向

采用简洁的桌面应用布局：侧栏导航、顶部搜索与重新检测、主体软件卡片或列表、详情抽屉。软件卡片展示图标、名称、安装版本、独立的安装状态与汉化状态，以及当前可用操作。提供浅色/深色主题、清晰层级、适度圆角与留白、键盘焦点及非纯颜色状态提示，不用大面积装饰或图表挤占软件管理区域。

默认展示已检测到的软件，可切换查看全部支持目录；未安装的软件保留在目录中，不伪造安装结果。首屏有加载、未发现软件、部分检测失败和检测完成状态。具体布局、状态与验收见 [任务计划](doc/task.md)。

## 3. 功能规划

### 工具管理

- 检测安装位置、版本、安装渠道与运行状态，并允许用户手动选择安装路径。
- 同一工具的多个安装实例分别管理，避免修改错误实例。
- 展示未安装、未验证、不兼容、可应用、已应用、更新后失效、需要恢复等状态。
- 兼容性按工具、版本、操作系统、架构、安装渠道及目标资源指纹判定；不能只比较版本号。

### 汉化管理

- 优先使用工具官方提供的语言设置、语言包或扩展机制。
- 确需修改本地资源时，仅使用已验证的定位规则与替换策略，并事先展示受影响文件和风险。
- 应用前执行 dry-run：验证匹配位置、匹配数量、原始指纹、占位符及写入权限。
- 展示汉化包版本、适配范围、来源、变更摘要和人工验证情况。
- 未知版本、匹配异常或资源冲突时拒绝修改，不进行无差别全局字符串替换。

### 备份、恢复与升级

- 修改前建立可校验的备份与操作清单；备份失败不得继续修改。
- 同一安装实例使用互斥锁；写入前再次校验资源，防止检查后文件被更新。
- 尽可能使用临时文件与原子替换；多文件操作记录事务日志，失败或中断后能够恢复。
- 重复应用同一方案不得产生重复替换或覆盖原始备份。
- 恢复前校验当前文件：若工具已升级或被其他程序修改，应停止自动覆盖并给出处理建议。
- 检测工具更新导致的汉化失效，提示重新检查；首期不静默重新应用、不安装常驻自动修复任务。

### 日志与诊断

- 记录检测、预览、备份、写入、验证与恢复结果，提供可理解的中文错误说明。
- 日志对用户名、敏感路径、token、API key 和配置内容进行脱敏。
- 诊断导出须由用户主动触发，支持预览，不默认包含目标软件的私有资源。

## 4. 候选工具适配策略

| 候选工具 | 首先调查 | 接入门槛 |
| --- | --- | --- |
| Claude Code | 区分 CLI 与 IDE 扩展；分别调查安装渠道、发行格式、官方本地化能力和可见文案来源 | 明确一个产品形态与安装渠道，在合法本地样本上验证应用、启动与恢复 |
| Claude Desktop | 官方语言能力、各平台安装方式、签名与完整性校验、资源位置 | 确认存在无需绕过平台保护的可维护方案，否则仅检测并说明限制 |
| Antigravity | 核实具体产品、发行来源、版本、官方语言包或扩展机制 | 明确产品身份与可行性后再确定适配技术，不预设内部框架 |

调查结论须记录具体版本、平台、渠道、验证日期及证据。某一版本的验证结果不能自动推广到其他版本。

## 5. 架构规划

采用「管理界面 + 应用服务 + 通用引擎 + 工具适配器 + 声明式汉化包」分层。

| 模块 | 职责 |
| --- | --- |
| 管理界面 | 工具列表、兼容性、变更预览、确认、进度、恢复与诊断 |
| 应用服务 | 编排流程、权限边界、实例锁与操作状态 |
| 通用引擎 | 文件校验、备份、事务日志、写入、恢复与审计 |
| 工具适配器 | 检测实例、识别版本、定位资源、生成计划与验证效果 |
| 汉化包 | 保存翻译条目、匹配约束、兼容条件和包版本，不执行任意脚本 |

适配器建议能力：`detect`、`inspect`、`checkLocalization`、`checkCompatibility`、`plan`、`verify`；计划区分应用与卸载汉化。实际文件修改与恢复统一交由引擎执行，避免各适配器自行实现安全逻辑。

汉化包计划包含：包标识、工具标识、包格式版本、适配版本、平台、架构、渠道、目标相对路径、原始指纹、匹配数量、翻译条目、占位符约束及验证记录。远程分发前须补齐可信来源与签名验证机制；仅有哈希不能证明发布者身份。

### 建议目录（尚未创建）

## 6. 本地化与安全边界

- 只修改用户可见文案，不翻译 JSON key、枚举、环境变量、工具名、命令名、路径、API 字段或协议标识。
- 保留占位符、转义序列、ANSI 控制码、快捷键和复数规则；翻译后必须校验。
- 中文提示、spinner 配置、模型输出语言与应用界面本地化分开标注，不将「提示模型用中文回复」视为完整界面汉化。
- 配置合并保留用户已有字段；不得覆盖账号、API、权限、Hook、MCP 或 statusLine 等无关配置。
- 不修改运行中被占用的可执行文件，不强制终止进程，不关闭自动更新、安全软件、签名检查或系统完整性保护。
- 遇到受保护目录或签名约束，解释限制并停止，不默认提权或绕过保护。
- 汉化包路径必须受安装根目录约束，并检查路径穿越、符号链接及目录联接等逃逸风险。
- 不重新分发目标软件、完整资源或含私有信息的样本；使用前核实许可证、服务条款和商标要求。本项目与相关厂商不存在官方隶属关系。

## 7. MVP 验收目标

1. 至少完成一个候选工具在一个明确版本、平台和安装渠道上的验证。
2. 能检测正确实例并生成只读预览，未知版本不会被修改。
3. 能在备份成功后应用经人工审核的翻译，并通过资源与实际界面验证。
4. 重复应用保持幂等；部分失败、文件占用、磁盘不足和中断场景有明确处理结果。
5. 正常恢复后文件内容与备份一致；目标已升级时不会被旧备份自动覆盖。
6. 不影响原有启动与核心功能，不改变账号、API、权限和用户无关配置。
7. 支持矩阵、限制、操作说明和验证记录与实际能力一致。
